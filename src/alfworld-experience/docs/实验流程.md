# ALFWorld 轨迹对比与经验进化

使用 ICLR 2021 ALFWorld 纯文本环境，在本机 Qwen3-14B Q4_K_M 上积累经验库。执行、反思、修正都调用同一个本地模型；模型权重固定。

## 快速运行

当前机器的依赖与数据已准备。双击 `开始实验.command`，或在本目录执行：

```sh
./scripts/run.sh prepare
./scripts/run.sh check
./scripts/run.sh run --run-dir runs/main
```

需要先启动模型服务：`../qwen-local/启动服务.command`。`开始实验.command` 会自动启动它。完整实验在前台运行，按 Ctrl+C 中断；再次运行同一命令会续跑。运行时阻止空闲睡眠，关闭占内存较多的其他应用。

换机器或重建环境时运行 `安装环境.command`。依赖固定在 `pyproject.toml`，本机完整版本记录在 `requirements.lock.txt`。安装只包含文本环境，不下载视觉模型。

## 题池和轮数

当前训练、扩展和最终测试均只选三类处理后放置任务：`pick_clean_then_place_in_recep`（清洗）、`pick_heat_then_place_in_recep`（加热）、`pick_cool_then_place_in_recep`（冷却）。这里的“中等难度”是按动作链长度划定的实验范围，并非官方难度标签。筛选在测试执行前固定，不根据模型成败挑题。

| 本实验用途 | 官方数据来源 | 题池数量 |
| --- | --- | --- |
| 原题池 | train 20 道 + valid_seen 累计转入 20 道 | 40 |
| 扩展题池（开发数据） | valid_seen 累计转出 20 道后 | 48 |
| 最终冻结测试（处理后放置） | valid_unseen | 20 |

这里的最终测试是从官方公开 `valid_unseen` 中留出的实验测试集，不是隐藏测试服务器成绩。扩展题参与经验修订，不能用作独立测试效果的证据。

- 随机种子为 42。保留从官方 train 随机抽取的原 20 道训练题，从原 68 道扩展池累计无放回随机转入 20 道，得到 40 道训练题。本次新增 10 道，原有 30 道及顺序保持不变。转入题仍保留 valid_seen 来源标记，并从扩展池移除；最终测试原 20 道保持不变。只选择官方标记可解的文本任务，排除 movable 与 Sliced。
- 总共进化 **40 轮**。按 `data/manifests/development.json` 中 `train` 数组的既有顺序，从第 1 道到第 40 道逐题执行，每题一轮，不再随机抽取或重新打乱。当前清单保留原 30 道题的顺序，再追加本次转入的 10 道题。
- 每轮从 48 道扩展池中无放回抽取 **一道**相同任务类型的题，优先改变物体、目标位置、场景。不会每轮跑完整个扩展池。
- 原题验证通过后只运行一次该轮扩展题：成功直接接收候选，失败才调用修正模型。全成功跳过、候选原题失败时，不执行扩展题；跳过或拒绝也计入一轮。
- 三份清单互不重叠，最终测试场景来自官方 unseen 划分。官方三部分的可用任务分别为 1642/68/75 道，转移后实际题池为 40/48/20。扩展池包含清洗 21 道、加热 11 道、冷却 16 道，足够无放回匹配 40 轮；训练池相应为 14/10/16 道。

题目与抽样计划固定在 `data/manifests/`。测试清单独立存放；进化模块只加载开发清单与轮次计划。修改题池配置后必须重建清单并使用新运行目录，不能混用既有结果。

## 每轮流程

1. 固定经验快照 M_t。原题独立执行三次，环境使用同一个种子和初始状态，每条轨迹的动作采样种子不同，对话和行动历史互不共享。
2. 有成功与失败时随机配成一对；全失败时优先选择行为不同的两条；全成功则跳过。配对种子、真实结果和轨迹 ID 全部保存。
3. 反思模型基于完整的动作—反馈轨迹生成一条候选经验，只包含触发条件、建议和例外，不要求原文引用或引用步号。失败—失败对不会被标成正确示范。程序不按物体类型、编号、场景标识或关键词过滤经验内容，也不自动改写。生成的候选直接进入原题执行验证；扩展题失败后的修订按现有流程直接追加。普适性由提示词约束。
4. 临时追加候选经验，只重跑原题一次；失败直接舍弃，保留旧经验库。
5. 原题通过后，只执行一次本轮扩展题。扩展题成功：直接接收候选经验，不调用修正模型。扩展题失败：才根据轨迹审阅并最多修正一次；没有明确问题时保留候选原文，修正不要求引用。
6. 将选定的候选或修订经验直接追加到旧经验库，提交 M_{t+1}。扩展失败后不再重跑题目，也不进行融合和回归；旧经验内容保留。

每轮最多 **5 条执行轨迹**：3 条初始轨迹、原题验证 1 条、扩展反馈 1 条。候选原题失败时为 4 条，全成功跳过时为 3 条。最终新增经验可能少于 40 条。

记录中区分“两题均通过、直接接收”“原题通过、扩展失败后保留候选”和“修正后未经复验”，不会把修正前的成功标记成修正后的验证结果。

## 最终测试

40 轮结束后写入 `memory_final.json` 并冻结。20 道测试题各自重置环境、清空历史，测试阶段不再更新经验。

默认先用空经验评测 20 道题，再按清单训练 40 轮，冻结经验后评测同一组 20 道题，共 40 条评测轨迹；两组使用相同动作与环境种子，独立重置。基线保存后直接复用，不重复执行。成功与否只取环境的 `won`，不使用模型自评。报告成功率、平均步数与成功率差值。

原题的一次成功用于筛选；扩展成功直接入库，扩展失败审阅后直接入库，修订经验不复验。最终效果通过冻结测试比较。20 题结果样本较小，不能据此声称统计显著性。

## 参数与复现

全局执行提示词位于 `prompts/actor.txt`，明确 TextWorld 的放置语法为 `move OBJECT to RECEPTACLE`，并提示手持限制、到达位置、容器开启、目标优先和无效动作恢复。兼容旧 `put ... in/on ...` 文本时，程序仅将其翻译为等价的 `move ... to ...`；原始输出与翻译标记都记录在轨迹中。

每次动作输入包含由本条轨迹可见反馈重建的状态笔记，记录当前位置、持有物品、已检查位置和连续无效动作。笔记在每条轨迹开始时清空，不读取隐藏物体位置、专家计划或合法动作列表。初始经验与最终经验评估使用相同的公共提示和状态处理。

`configs/default.yaml` 包含数量、轮数、最大步数与模型参数。默认每条轨迹最多 50 个动作；只给模型初始观测与本次可见交互，不提供专家计划、隐藏状态或 admissible actions。

执行上下文为 4096 token，保留完整经验与初始任务，近期历史预算为 1000 token，可见状态笔记预算为 550 token；较早的行动历史按窗口淘汰并标注，关键状态由可见反馈笔记保留。原始轨迹始终完整保存。反思/修正上下文为 8192 token，使用 Qwen 官方分词器计数；完整反思输入放不下时明确记录原因，不静默截断轨迹或经验。

16GB 内存余量较紧。环境/API 故障会停止实验，保留进度，**不会伪装成任务失败**。不完整的执行从相同初始状态重放，复用已完成模型调用，逐步核对反馈后继续。代码、配置、数据清单、模型摘要、分词器及关键依赖版本都会记录；发生变化时拒绝覆盖旧实验。

固定种子与缓存便于复现，但不同硬件/软件上的 Metal 推理不保证逐位相同。

```sh
# 仅准备清单 / 检查环境 / 两步真实联通检查
./scripts/run.sh prepare
./scripts/run.sh check
./scripts/run.sh smoke
./scripts/run.sh pilot

# 分开进化与冻结测试
./scripts/run.sh evolve --run-dir runs/main
./scripts/run.sh test --run-dir runs/main

# 查看进度 / 重新生成报告
./scripts/run.sh status --run-dir runs/compare40-20261103-195520
./scripts/run.sh report --run-dir runs/compare40-20261103-195520

# 协议分支测试（脚本替身，不是 benchmark 实验结果）
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v

# 安装官方数据后，启用真实环境任务完成检查
ALFWORLD_INTEGRATION=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

## 输出

最近一次实验保存在 `runs/compare40-20261103-195520/`，包括 `report.md`、`report.json`、`memory_final.json`、每轮 `rounds/`、全部 `episodes/`、完整模型输入输出 `model_calls/`、逐步事件 `events.jsonl` 和实验身份 `run_metadata.json`。

`runs/smoke/` 用于少步数联通诊断，`runs/pilot*/` 用于完整开发任务预检，均不计入正式结果。当前版本已通过 65 项检查，包含真实环境任务完成、三类题池筛选和同结构配对检查。

最终测试选择的调整单独保存在 `evaluation_metadata.json` 和 `evaluation_manifests/`，原始训练元数据保留。只有测试任务类型筛选发生变化、开发清单相同且执行/学习代码与冻结快照完全一致时才允许继续；修改训练种子、动作策略、模型或开发题清单仍会拒绝混用运行结果。

本机只保留最近一次完整实验，其余旧运行、诊断日志和旧题池备份已删除。模型、官方数据集及当前清单保留。本实验只覆盖三类处理后放置任务，不能代表全部六类任务。

官方参考：[ALFWorld 仓库及 ICLR 2021 引用](https://github.com/alfworld/alfworld)、[官方默认配置](https://github.com/alfworld/alfworld/blob/master/configs/base_config.yaml)。


## 反思输入预算

反思上下文为 8192 token，预留输出 1536 token。采用无损紧凑格式：相同任务类型及初始观察在 `contexts` 中仅保存一次；每条轨迹引用自己的上下文；`step_fields` 一次声明步号、动作、反馈、得分和成功标记，各步用数组保存。原始轨迹不变，所有步骤和反馈均保留；不同原题、扩展题的初始观察分别保存。

紧凑格式减少共同信息与字段名的重复占用，上下文上限仍为 8192。每次调用前检查预算，完整输入放不下时明确报错。步号保留为执行记录；候选与扩展修正均不要求引用。


## 当前反思提示词

候选生成与扩展修正分别使用 `prompts/propose.txt`、`prompts/review.txt`。当前候选生成模板约 325 token，执行模板约 385 token；生成输入顺序为当前任务原文、两条真实结果及完整紧凑轨迹；生成模块不读取或传入旧经验原文。任务指令从可见初始观察中提取，不加入隐藏状态或答案。执行智能体继续使用当前经验，扩展修正模块仍使用原上下文，但仅在扩展题失败时调用。

候选只含触发条件、建议和例外，无需引用。反思逐条核对正确目标的获取、处理和放置，定位最早未解决的阻断点，检查位置、手持、容器状态和命令形式；不混合轨迹进展或臆测失败原因。经验使用抽象角色，明确恢复动作，不写原题细节、不举例。执行按经验触发条件使用建议，区分导航位置与物体，拿到正确目标后连续完成处理和放置。程序不增加内容机械过滤，经验去重保持原设置。

## 扩展题转入训练池

配置 `splits` 表示最终池大小：40/48/20；`pool_transfer.extension_to_train: 20` 表示先建立 20 道基础训练题和 68 道扩展题，再累计转移 20 道；其中前 10 道是此前转入，本次只追加后 10 道。转移种子与完整题目 ID 记录在 `data/manifests/summary.json` 的 `pool_transfer` 中。测试清单保持原样，三个池的题目 ID 和环境哈希互不重叠。

仅保留 `runs/compare40-20261103-195520/` 中最近一次完整实验及当时的源码快照。当前提示词已替换，未启动新实验；保留结果使用的是该目录中的历史源码快照。流程版本为 `original_once_extension_failure_review_append_v2`。训练计划为 `rounds: 40`、`original_order: manifest`，监督脚本读取实际计划轮数。后续实验使用独立目录。

## 完整实验监督

使用以下入口监督 40 轮训练及后续 20 道冻结测试，每 1800 秒记录一次进度：

```sh
.venv/bin/python -u scripts/supervise_evolution.py --run-dir runs/sequential-40 --interval 1800 --with-test
```

配置 `evaluation.baseline_before_training: true` 时，完整 `run` 先完成空经验基线 20 题，再顺序训练 40 轮，冻结后完成最终经验 20 题；最终对比复用训练前基线，共 40 条评测轨迹。单独 `evolve` 只训练；先基线再训练的完整实验使用 `run` 或监督入口 `--with-test`。监督状态记录在 `supervision.json` 和 `monitoring.jsonl`；测试完成前不会标记完整实验成功。临时服务故障最多自动续跑两次，测试阶段支持保留进度后续跑。

训练前基线写入 `baseline_results.json`；分阶段进度为 `baseline_progress.json`、`status.json` 和 `test_progress.json`。训练不接收基线题目、结果或轨迹。最终对照结果写入 `report.md`、`test_results.json` 和 `evolution_summary.md`。不加 `--with-test` 时只执行训练。
